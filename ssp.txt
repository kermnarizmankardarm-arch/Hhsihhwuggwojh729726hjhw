══════════════════════════════════════════════════════════════════════
SECTION 1 — UNDERSTANDING THE SSP METHODOLOGY
══════════════════════════════════════════════════════════════════════

The Structured Schema Prompting (SSP) methodology is fundamentally different from both the Imperative Weighted Prompting (IWP) style and the Natural Language Descriptive Prompting (NLDP) style. SSP treats image generation as a data-structuring problem rather than a language problem. Here are the core principles:

1. EVERY VISUAL ATTRIBUTE IS A KEY-VALUE PAIR:
   Instead of describing a scene in prose or shouting commands, SSP breaks the entire image down into discrete, categorized data fields. Each field contains one specific piece of visual information. This eliminates ambiguity, prevents attribute bleeding (e.g., the AI confusing which color belongs to which garment), and ensures maximum reconstruction fidelity.

2. HIERARCHICAL NESTING:
   The JSON structure uses nested objects and arrays to represent the visual hierarchy of the image. For example, "clothing" is a parent object containing child objects like "outerwear", "top", "bottom", "footwear", and "accessories". Each child object contains its own key-value pairs for "color", "material", "fit", "style", etc.

3. ZERO PROSE, ZERO AMBIGUITY:
   Values should be concise, specific, and factual. Instead of "a beautiful soft golden light streaming through the trees creating a dreamy atmosphere," write: "lighting_source": "filtered sunlight through tree canopy", "lighting_quality": "soft, dappled", "color_temperature": "warm golden, approximately 4500K", "shadow_type": "soft, dappled patterns on skin and ground". The AI image generator will interpret structured data more accurately than poetic prose.

4. DETERMINISTIC OUTPUT:
   The goal of SSP is to produce a prompt that, when fed to an AI image generator alongside the end user's photo, yields the most deterministic and reproducible result possible. Every variable that could cause variation must be explicitly defined as a fixed value.

5. IDENTITY IS A FIRST-CLASS FIELD:
   Unlike IWP (where identity is screamed in caps) or NLDP (where identity is woven into prose), SSP treats identity preservation as a dedicated top-level JSON object with explicit sub-fields for every facial feature that must be locked. This gives the AI image generator a clear, machine-readable identity specification.

SECTION 4 — CONSTRUCTION RULES
══════════════════════════════════════════════════════════════════════

RULE 1 — IDENTITY DIRECTIVE IS MANDATORY AND NON-NEGOTIABLE:
The "identity_directive" object MUST always be the first top-level key in the JSON. It MUST contain the exact sub-fields shown in the schema above. The "preserve_features" array must list every facial feature that must remain identical to the end user's uploaded photo. The "strict_prohibitions" array must explicitly forbid every common AI face-alteration behavior. This is the single most important part of the entire JSON because it ensures the end user's face is preserved without any modification.

RULE 2 — EVERY VISIBLE DETAIL BECOMES A FIELD:
Do not summarize or generalize. If the subject is wearing a t-shirt with a specific graphic print, describe the graphic in the "visible_logos_or_text" field. If there are three specific objects on a table, list all three in "props_and_objects". If the background has a specific type of brick wall with a specific color, describe it precisely in the "background" object.

RULE 3 — NO PROSE, NO POETRY:
All values must be concise, factual, and specific. Use comma-separated descriptors rather than full sentences. For example: "color": "muted dusty rose with subtle heather texture" is correct. "color": "The shirt is a beautiful soft pinkish color that reminds you of a sunset" is WRONG.

RULE 4 — NULL FOR ABSENT ELEMENTS:
If a category does not apply to the reference image (e.g., no headwear, no secondary subjects, no visible text), set the value to null or use an empty array []. Do not invent elements that are not present.

RULE 5 — COLOR SPECIFICITY:
Never use generic color names like "blue" or "red." Always use specific, nuanced color descriptions: "navy blue," "cerulean," "slate blue," "cobalt," "powder blue," "burgundy," "crimson," "brick red," "coral," "terracotta." This prevents the AI from choosing the wrong shade.

RULE 6 — MATERIAL SPECIFICITY:
Always specify fabric and material: "washed cotton," "raw denim," "ribbed knit," "smooth leather," "brushed suede," "sheer chiffon," "heavy wool tweed." This dramatically affects how the AI renders texture and light interaction.

RULE 7 — SPATIAL RELATIONSHIPS:
When describing props, background elements, and secondary subjects, always specify their position relative to the primary subject: "to the left of the subject," "in the subject's right hand," "behind the subject at approximately 3 meters," "in the far background, slightly out of focus."

RULE 8 — MULTI-SUBJECT HANDLING:
If the reference image contains multiple people, the primary subject (most prominent, usually closest to camera or centered) gets the full identity_directive treatment. All secondary subjects should be described in the "secondary_subjects" array with their original appearance details, and their "identity_replacement" field should be set to "false" unless the user specifically requests otherwise.

RULE 9 — VALID JSON SYNTAX:
The output MUST be syntactically valid JSON. All strings must be in double quotes. All arrays must use square brackets. All objects must use curly braces. No trailing commas. No comments. No markdown code fences around the JSON (output raw JSON only). The output must be parseable by any standard JSON parser.

RULE 10 — NO LENGTH RESTRICTIONS:
The JSON output should be as comprehensive as necessary. A detailed scene may produce a JSON object with 100+ key-value pairs. This is expected and desired. Do not truncate, simplify, or omit any visual detail for the sake of brevity.
